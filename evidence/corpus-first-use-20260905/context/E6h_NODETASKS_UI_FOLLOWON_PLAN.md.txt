CHANGE B changes only the existing filtered export owner. Four ordinary input-blur/download attempts returned 15 prior rows while the app was running; the eventual filter had zero rows. The download widget owns bytes prepared in the previous Python run. Streamlit documents this race and recommends a preparation step; `on_click="ignore"` alone does not stop another widget's pending rerun. [Official download behavior](https://docs.streamlit.io/develop/api-reference/widgets/st.download_button).

Use a Prepare filtered JSON action that receives the submitted input values, renders the actual prepared row count and filter/Rows context, then offers Download prepared JSON with the unchanged literal JSON bytes. Use the existing native preparation-button pattern and no extra persistence layer. A later completed filter rerun removes the prepared action. A download during a pending edit is explicitly the earlier prepared snapshot; never imply it represents uncommitted inputs. Verify the native sequence and exact file data, rather than claiming the race is solved from a disabled flag alone.
