PR1 marks the four vendored signatures `migration-source`. NodeKit's decision contract defines that as an authoritative source assigned for extraction; these files are frozen copies of NodeRoom provenance. Use `migration-copy`, keep the existing NodeAgent origins, and correct PR1's stale statement that `canonicalFor` must remain empty. The independent corpus receipt is the permitted owned concept. No NodeKit registry change or NodeAgent ownership transfer is required.

**Validator trust boundary:** source-index paths are checked with a prefix assertion, but a failing assertion does not stop the subsequent file read. A path containing `upstream/noderoom/../../...` can pass the prefix and escape the intended source subtree; links are followed as well. This is a static, concrete safety gap for changed/untrusted corpus inputs, though the exact reviewed tree contains neither case. Before accepting adversarial fixture handling, reproduce it using a harmless sentinel outside the allowed subtree, then enforce the existing public-source rule once before that read. Do not read actual external/private files. This needs `scripts/validate-catalog.mjs` and the existing scenario test owner if confirmed; no new path framework or dependency.

**Current handoff:** README/bridge URLs use8502 while the command leaves the port unspecified; ordinary fresh Streamlit defaults to8501. The old storyboard's9,140 expectation is stale and overwrites tracked media; keep its limitation explicit and do not make that capture a prerequisite for this proof. No UI repair is authorized by this review.

## Receipt semantics and failure limits

`doctor` resolves paths from `import.meta.url`, checks Node>=20, required files and narrow manifest text. It does **not** validate the corpus or enforce the NodeKit registry. `check` runs doctor, two existing tests and `proof`. `proof` uses the current directory, recomputes content and indexed-source hashes, compares exact serialized receipt bytes, and exits nonzero for stale/missing receipt or source drift. `validate` explicitly writes a new receipt and must not be used to erase baseline failure.

The receipt is deterministic corpus integrity evidence, unsigned and without a Git commit identity. It binds catalog/schema bytes and the indexed source aggregate. It does not bind Streamlit, producer/test source, installed dependencies, rendered UI, an upstream NodeRoom commit, or an official score. Record source-export and execution bindings separately. `releaseReady: true` means corpus validation only.

Unknown/conflicting flags return2; logical catalog violations and source drift return1. Malformed JSON, missing files or invalid shapes can throw and still fail nonzero, without a structured receipt. The schema file is hashed but not executed as a schema validator. Existing tests cover the real committed corpus and ownership text only; malformed inputs, stale/tampered receipt, changed source, concurrent reads and failure recovery are not covered. No atomic filesystem snapshot or concurrent-writer guarantee exists; run proof against frozen inputs, reject source movement in the harness, and preserve uncertainty.
